# Antigravity Vibe Coding Tutorial: RealWorld Implementation

이 문서는 Antigravity를 활용하여 RealWorld 애플리케이션을 구현하는 과정을 통해 "바이브 코딩(Vibe Coding)"의 흐름을 설명하는 튜토리얼입니다.

**바이브 코딩이란?**
AI 에이전트에게 구체적인 코드를 지시하는 대신, **의도(Intent)**와 **맥락(Context)**을 제공하고, 에이전트가 생성한 결과물을 **리뷰(Review)**하고 **조정(Refine)**하며 개발하는 방식을 말합니다.

---

## Step 1: 프로젝트 정의 및 리서치 (Scoping)

가장 먼저 프로젝트의 목표와 사양을 정의합니다.

**사용 프롬프트:**
> "리얼월드 앱을 풀스택으로 구현하려고해. 앱 사양은 이 URL의 내용을 그대로 사용해줘... 테크 스택은 Agentic Coding Recommendations에서 Armin이 제시한 내용을 기반으로 정해줘... PRD, 테크스택을 문서화 해줘."

**목적:**
- 외부 문서(URL)를 기반으로 요구사항을 파악하게 함.
- 특정 기술적 철학(Armin's recommendations)을 따르도록 지시.
- 결과물을 코드가 아닌 **문서(PRD, Tech Stack)**로 먼저 받아 방향성을 검증.

**실행 결과:**
- 에이전트가 URL을 분석하여 기능 명세(PRD)를 작성함.
- 초기에는 Armin이 Flask 창시자라는 점 때문에 Python을 제안함 (오류 발생).

**💡 개선점/Insight:**
- 에이전트가 "Agentic Coding Recommendations"라는 특정 문구를 찾지 못할 경우, 일반적인 지식에 의존할 수 있습니다. 중요한 참조 자료는 구체적인 링크나 텍스트를 직접 제공하는 것이 더 정확합니다.

---

## Step 2: 방향성 교정 (Refinement)

에이전트의 제안(Python)이 의도와 다를 때, 이를 교정합니다.

**사용 프롬프트:**
> "아로민 로나허의 블로그에 따르면 백엔드 언어는 go언어를 써야 하는거 아냐? 왜 python을 선택했어?"
> "테크 스택의 기술들에서 사용될 버전을 각 기술의 LTS최신버전으로 명시해줘."

**목적:**
- 에이전트의 잘못된 추론(Python 선택)을 지적하고 올바른 방향(Go)으로 유도.
- "현 시점"의 최신 정보를 검색하도록 하여 구체적인 버전(Go 1.25.4, Node 24 등)을 확정.

**실행 결과:**
- 에이전트가 웹 검색을 통해 Armin이 Go를 추천한다는 사실을 확인하고 문서를 수정함.
- 최신 버전 정보를 검색하여 Tech Stack 문서를 구체화함.

**💡 개선점/Insight:**
- 에이전트와 논쟁하듯 질문("왜 Python을 선택했어?")하면, 에이전트는 자신의 근거를 재검토하고 수정합니다. 이 과정이 바이브 코딩의 핵심입니다.

---

## Step 3: 인프라 및 형상 관리 (Setup)

구현 전에 작업 환경을 구축합니다.

**사용 프롬프트:**
> "현재 작업 리포지토리를 github에 등록해줘..."
> "각 폴더에 리드미를 추가해줘"

**목적:**
- 깃허브 연동 및 프로젝트 구조(README) 잡기.

**실행 결과:**
- 로컬 git 초기화, 커밋, 원격 리포지토리 생성 및 푸시 완료.
- 폴더별 README 생성으로 구조화.

---

## Step 4: 상세 계획 수립 (Planning)

본격적인 코딩 전에 작업 단위를 세분화합니다.

**사용 프롬프트:**
> "앞으로 진행할 작업들을 최대한 세분화 해서 /docs/TASKS.md 에 문서화해줘."

**목적:**
- 에이전트가 수행할 작업의 로드맵을 그림.
- 이후 에이전트가 스스로 진행 상황을 체크할 수 있는 기준점 마련.

**실행 결과:**
- Phase 1 ~ Phase 6까지 단계별 작업 목록이 생성됨.

---

## Step 5: 실행 및 검증 (Execution & Verification)

계획된 작업을 에이전트에게 위임하여 실행합니다.

**사용 프롬프트:**
> "@[docs/TASKS.md] 에 대해 리뷰해줘." (Task 모드 진입)

**목적:**
- 계획(TASKS.md)을 바탕으로 실제 구현(Phase 1)을 시작.
- 에이전트가 스스로 계획(Plan) -> 실행(Execute) -> 검증(Verify) 사이클을 돌도록 함.

**실행 결과:**
- **Backend**: Go 모듈 초기화, 기본 서버 코드 작성.
- **Frontend**: Vite 프로젝트 생성 (초기 충돌 발생 시 스스로 해결하고 수동 생성).
- **Database**: Docker Compose 설정.
- **Verification**: 모든 서버를 실행하고 `walkthrough.md`에 결과를 리포트함.

**💡 개선점/Insight:**
- 에이전트는 실행 중 오류(예: 폴더가 비어있지 않아 Vite 생성 실패)가 발생하면, 스스로 우회 방법(수동 파일 생성)을 찾아 해결합니다. 사용자는 결과물(`walkthrough.md`)만 확인하면 됩니다.

---

## Step 6: 규칙 및 워크플로우 설정 (Automation)

단순 코딩을 넘어, 에이전트가 프로젝트의 규칙을 이해하고 반복 작업을 자동화하도록 설정합니다.

**사용 프롬프트:**
> "workflow를 만들려면 어떻게 해야해?"
> "rule은 어떻게 작성하는가?"
> "ghp 명령을 사용해서... 프로젝트에 등록해줘."

**목적:**
- **Rules**: `.agent/rules/`에 기술 스택, 코딩 스타일 등을 정의하여 에이전트가 매번 물어보지 않고도 일관된 코드를 작성하게 함.
- **Workflows**: `.agent/workflows/make_pr.md`와 같이 자주 하는 작업(PR 생성)을 자동화된 절차로 정의.

**실행 결과:**
- **Rules**: `tech_stack.md`, `coding_style.md` 등을 생성하여 "Go + SQLite", "한국어 주석" 등의 규칙을 확립.
- **Workflows**: `/make_pr` 명령 하나로 "변경사항 확인 -> 이슈 생성 -> 브랜치 생성 -> PR 생성 -> 리뷰"까지 일괄 처리.

**💡 개선점/Insight:**
- 에이전트에게 "규칙"을 파일로 주면, 이후 작업부터는 그 규칙을 스스로 참고합니다. 이는 프롬프트 엔지니어링을 파일 시스템 레벨로 확장한 것입니다.

---

## Step 7: 도구 실패 대응 및 외부 협업 (Adaptability)

사용자가 제공한 커스텀 도구(`ghp`)가 실패했을 때의 대처와 외부 리포지토리와의 상호작용입니다.

**상황:**
- 사용자가 `ghp`라는 커스텀 도구 사용을 요청했으나, 실행 시 JSON 파싱 에러 발생.
- 소스 코드가 없어 수정 불가능.

**대응:**
1. **진단**: 에러 로그 분석 및 소스 코드 부재 확인.
2. **대안 제시**: 공식 도구인 `gh` CLI 사용 제안 및 승인 획득.
3. **외부 기여**: 사용자의 요청으로 `ghp` 원본 리포지토리에 "기능 추가 요청(Feature Request)" 이슈를 대신 작성하고 등록함.

**💡 개선점/Insight:**
- 에이전트는 단순히 주어진 도구만 쓰는 것이 아니라, 도구가 고장 났을 때 **진단 -> 보고 -> 대안 제시**의 프로세스를 수행할 수 있습니다.
- 또한, 내 프로젝트뿐만 아니라 **외부 오픈소스 프로젝트**에 이슈를 등록하는 등 "개발자의 대리인"으로서의 역할도 수행합니다.

---

## 결론

이 튜토리얼은 **"문서화(Spec) -> 교정(Refine) -> 계획(Plan) -> 위임(Delegate)"**의 흐름을 보여줍니다. 코드를 한 줄도 직접 짜지 않고, 에이전트와의 대화와 문서 리뷰만으로 풀스택 프로젝트의 기반을 완벽하게 구축했습니다.
